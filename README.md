## Подготовительные мероприятия
Необходимо выбрать общую папку, которая будет использоваться для передачи информации между виртуальными машинами и хостом. Для этого следует перейти в **настройки ВМ**, выбрать раздел **Options**. Во вкладке **Shared Folders** выбрать режим **Always enabled**, затем нажать кнопку **Add** для добавления общей папки:

![ScreenShot](assets/1.png)

Здесь укажите **имя папки** и **путь к ней**, должен быть установлен атрибут **Enabled**:

![ScreenShot](assets/2.png)

Результат выполнения описанных действий должен выглядеть так:

![ScreenShot](assets/3.png)

> Добавить общую папку необходимо для **всех ВМ** под управлением **Windows 10** (все машины за исключением координаторов)!

Далее необходимо перейти в **Панель управления => Сеть и интернет => Центр управления сетями и общим доступом => Изменение параметров адаптера**, нажать правой кнопкой мыши на сетевой адаптер, перейти в его **Свойства**, в пункте **IP версии 4 (TCP/IPv4)** произвести конфигурацию сетевого адаптера в соответствии с таблицей сетевых параметров, представленной в дополнительных материалах. Пример сетевой конфигурации для Net1-Open:

![ScreenShot](assets/4.png)

> Произвести сетевую конфигурацию нужно для **всех ВМ** под управлением **Windows 10**!

Вернитесь в **Центр управления сетями и общим доступом** и перейдите в пункт **Изменить дополнительные параметры общего доступа**. Здесь необходимо перевести все тумблеры в положение **Включено**, как показано ниже:

![ScreenShot](assets/5.png)

![ScreenShot](assets/6.png)

![ScreenShot](assets/7.png)

Перейдите **Панель управления => Система и безопасность => Брандмауэр Защитника Windows => Включение и отключение брандмауэра Защитника Windows**. Переведите оба тумблера в режим **Отключено**:

![ScreenShot](assets/8.png)

> Повторите действие на **всех ВМ** под управлением **Windows 10**

> Отключение брандмауэра необходимо, чтобы исключить **вероятность ошибки** на более поздних стадиях проектирования защищенной сети.

Перейдите в **Панель управления => Система и безопасность => Электропитание => Настройка отключения дисплея**. В обоих выпадающих списках выберите режим **Никогда**:

![ScreenShot](assets/9.png)

В заключение подготовительного этапа необходимо проверить **сетевую доступность** между виртуальными машинами в своих сетях с помощью утилиты командной строки **ping**:

### Задача 4.3. Разрешение доступа по SSH к координатору `Net1-Coord` от узла `Net2-Client`

По условию задания необходимо обеспечить возможность удаленного администрирования координатора `Net1-Coord` по протоколу SSH (порт 22 TCP) с рабочей станции филиала `Net2-Client` (`UserB`).  
Поскольку `Net2-Client` является полноценным защищенным клиентом сети ViPNet, данный трафик передается по шифрованному каналу и обрабатывается **Фильтрами защищенной сети**.

1. В веб-интерфейсе `Net1-Coord` откройте первую вкладку: **Межсетевой экран $\rightarrow$ Сетевые фильтры $\rightarrow$ Фильтры защищенной сети**.
2. Создайте разрешающее правило:
   - **Название:** `Allow SSH` (или `SSH`)
   - **Состояние:** **«Включено»** (зеленый тумблер)
   - **Действие:** **Пропускать трафик**
   - **Источники:** выберите узел **`UserB`** (или группу *Все клиенты*)
   - **Назначения:** выберите **`Мой узел`** (координатор `Net1-Coord`)
   - **Транспортные протоколы:** протокол **TCP**, порт **`22`**

![Таблица фильтров защищенной сети с включенным правилом для порта 22](my_screenshots/34_212030_vmware_dEXThodnE4.png)

4. **Проверка работоспособности SSH-подключения:**  
   Поскольку не во всех сборках Windows 10 предустановлен клиент OpenSSH, для проверки используется SSH-клиент **PuTTY** (в соответствии с формулировкой задания: *«При необходимости можно самостоятельно установить любой SSH-клиент»*).  
   
   В архитектуре защищенных сетей ViPNet удаленные узлы доступны клиентам по защищенным **виртуальным IP-адресам** (согласно таблице видимости в ViPNet Мониторе узел `Net1-Coord` имеет виртуальный адрес **`11.0.0.1`**).
   
   - На рабочей станции **`Net2-Client`** запустите утилиту **PuTTY**.
   - В поле **Host Name** введите адрес: **`11.0.0.1`**, порт: **`22`**, тип подключения: **SSH**.
   - Нажмите кнопку **Open**.

### Шаг 5.5. Проверка функционирования туннелирования (ICMP ping)

Для проверки работоспособности туннеля садимся за виртуальную машину **`Net1-Open`** (`192.168.10.50`) и выполняем диагностическую команду `ping` до незащищенного узла партнерской сети **`Net3-Open`** (`192.168.30.50`):

```cmd
ping 192.168.30.50
```

**Результат проверки:**
- Все отправленные ICMP-пакеты успешно доставлены без потерь (0% потерь).
- Время отклика составляет **2–3 мс**.
- Значение **`TTL=126`** строго подтверждает прохождение трафика через два промежуточных координатора-шлюза (`128 - 2 = 126`): пакет от `Net1-Open` попадает на `Net1-Coord`, шифруется в криптотуннель, передается по внешней сети на `Net3-Coord`, расшифровывается и доставляется целевому узлу `Net3-Open`.
