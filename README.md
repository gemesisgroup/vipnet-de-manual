![ScreenShot](assets/3.png)

## Задание 2. Создание структуры защищенной сети

### Задача 2.1. Развертывание защищенной сети и распределение ролей
#### Текст задания:
> Необходимо использовать рабочее место администратора (созданное ранее)
для создания структуры защищенной сети, развернуть с помощью технологии
виртуальных машин сеть предприятия и настроить необходимые АРМ в
соответствии с заданными ролями.
В итоге выполнения задания должны быть развернуты и настроены
следующие сетевые узлы защищенной сети (см. таблицу 1).

#### Таблица 1 - Узлы защищенной сети 
| Вирт. машина         | Название сетевого узла  | ПО ОС сетевого узла                                   | ОС сетевого узла                  | Имя пользователя сетевого узла |
|----------------------|-------------------------|-------------------------------------------------------|-----------------------------------|--------------------------------|
| Net1-Admin (ЦО)      | Администратор сети      | Administrator (БД, ЦУС сервер и клиент, УКЦ), Client  | Пользовательская или серверная ОС | AdmN                           |
| Net1-Coord (ЦО)      | Координатор офиса       | Coordinator                                           | HW-VA                             | CoordO                         |
| Net2-Coord (Филиал)  | Подчиненный координатор | Coordinator                                           | HW-VA                             | CoordB                         |

### Шаг 5.4. Настройка транзитных правил сетевого экрана для туннелируемого трафика

По умолчанию координаторы ViPNet блокируют транзитный трафик открытых сетей. Для обеспечения связности туннелируемых машин необходимо настроить разрешающие правила в веб-интерфейсах обоих координаторов:

1. В веб-интерфейсе **`Net1-Coord`** (`http://192.168.10.1:8080/`):
   - Перейдите в: **Межсетевой экран $\rightarrow$ Сетевые фильтры $\rightarrow$ Транзитные фильтры открытой сети**.
   - Нажмите кнопку **«Добавить»** ($+$):

![Добавление транзитного правила на Net1-Coord](my_screenshots/43_214103_vmware_oa69LtSFDT.png)

   - Создайте правило `Net1-Net3`:
     - **Источники:** координатор `Coord-1` (или подсеть `192.168.10.0/24`)
     - **Назначения:** координатор `Coord-3` (или подсеть `192.168.30.0/24`)
     - **Действие:** **Пропускать трафик**
   - Нажмите кнопку **«Сохранить»**:

![Параметры транзитного правила Net1-Net3](my_screenshots/45_214227_vmware_e74cT3wfAE.png)

2. В веб-интерфейсе **`Net3-Coord`** (`http://192.168.30.1:8080/`):
   - В разделе *Транзитные фильтры открытой сети* создайте симметричное правило `Net1-Net3 (open)`:
     - **Источники:** `Coord-3`
     - **Назначения:** `Coord-1`
     - **Действие:** **Пропускать трафик**
   - Сохраните и примените изменения:

### Шаг 5.5. Проверка функционирования туннелирования (ICMP ping)

Для проверки работоспособности туннеля садимся за виртуальную машину **`Net1-Open`** (`192.168.10.50`), открываем командную строку (`cmd`) и выполняем диагностическую команду `ping` до незащищенного узла партнерской сети **`Net3-Open`** (`192.168.30.50`):

```cmd
ping 192.168.30.50
```

**Результат проверки:**
- Все 4 отправленных ICMP-пакета успешно доставлены без потерь (0% потерь).
- Время отклика составляет **2–3 мс**.
- Значение **`TTL=126`** строго подтверждает прохождение трафика через два промежуточных координатора-шлюза (`128 - 2 = 126`): пакет от `Net1-Open` перехватывается `Net1-Coord`, инкапсулируется в зашифрованный туннель, передается координатору `Net3-Coord`, расшифровывается и передается целевому открытому узлу `Net3-Open`.

![Успешный пинг с Net1-Open на Net3-Open с подтверждением прохождения через туннель (TTL=126)](my_screenshots/48_214551_vmware_mh9ews2L14.jpg)
